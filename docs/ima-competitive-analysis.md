# Old Z 竞品深度分析报告

> 调研日期：2026-07-08
> 竞品：腾讯 ima（2.5.x）、Obsidian（1.12+）

---

## 一、ima 是什么

腾讯于 2024 年 11 月发布的 AI 智能工作台，定位"会思考的知识库 / 第二大脑"。覆盖 Win/Mac/iOS/Android/小程序等 9 个端。

核心功能：搜（问答检索）+ 读（文档解读）+ 写（AI 创作）

---

## 二、ima 的 7 大硬伤 → Old Z 的机会

### 1. 容量焦虑（最致命）
- 免费版仅 2GB，重度用户几天用完
- 用户原话："2G 够谁塞啊，我微信收藏早破 10G 了"

> **我们的机会**：OSS 成本极低，轻松做到免费 50G+

### 2. 隐私焦虑（第二大痛点）
- 所有文件强制上传腾讯云，必须微信/QQ 登录
- 协议对数据是否用于训练模型、是否加密等描述模糊
- 法律/金融/医疗等行业完全不敢用

> **我们的机会**：Electron 桌面端天然支持本地优先架构

### 3. 生态围墙
- 只打通腾讯文档，WPS/飞书/Notion 全不通
- 资料需要手动搬运

> **我们的机会**：做生态中立的工具

### 4. 组织能力弱
- 知识库扁平化设计，没有文件夹分类
- "知识库"和"笔记"两个模块割裂，操作逻辑不一致

> **我们的机会**：Files + Notes + Todos 三大模块无缝关联

### 5. 搜索质量不稳定
- 会混入共享知识库内容，缺少"只搜我的库"开关
- 事实类问题偶有幻觉

> **我们的机会**：标注"仅我的库 / 仅当前文档 / 跨库"的显式检索范围

### 6. 无法离线使用
- AI 推理全依赖云端，断网就废
- 不支持本地模型接入（Ollama/llama.cpp）

> **我们的机会**：Electron 端可以集成本地小模型

### 7. 不适合做任务管理
- ima 偏"查阅型知识库"，没有真正的待办/日程管理

> **我们的机会**：知识管理 + 行动管理一体化

## 六、ima 比我们强的地方 → 我们该学的

### P0 — 不改就是硬伤

#### 1. 知识库 RAG 检索 vs 全量灌入 Context

**现状**（`api/services/ai.ts:265-291`）：
```typescript
// buildChatContextMessage — 把所有数据 dump 进 system prompt
ctx.todos.forEach(t => parts.push(`- [ ] ${t.title} ...`));
ctx.files.forEach(f => parts.push(`- ${f.name} ...`));
ctx.notes.forEach(n => parts.push(`- ${n.title}: ${n.content.slice(0, 200)}`));
```

问题：
- 用户有 100 个文件时，context 太长被截断或塞不进去
- 文件内容只截取前 200 字符，找不到需要的信息
- 回答没有出处标注

**改进方案**：
1. 文件/笔记上传时做 embedding → 存向量
2. 提问时向量检索 top-5 相关片段 → 精准注入 context
3. 回答后标注来源：`> 📄 来自《季度财报.pdf》`

#### 2. AI 与编辑器的融合

**现状**：编辑器没有 AI 入口

**改进方案**：
- 笔记编辑器里选中文字 → 弹出 AI 浮动菜单（"润色 / 扩写 / 摘要 / 翻译"）
- 快捷键 `Ctrl+K` 呼出 AI 内联输入框
- 不离开编辑界面就能完成 AI 操作

#### 3. 文档上传后的自动 AI 处理

**现状**（`Dashboard.tsx:111-164`）：上传 → 存文件 → 手动打标签 `['拖拽上传']` → 结束

**改进方案**：
- 上传完成后自动调用一次 AI："给这个文件起 3-5 个标签，写一句中文摘要"
- 标签自动填充、摘要存为文件属性

### P1 — 重要但可以排后

#### 4. 搜索范围显式切换

Chat 输入框上方加标签行：
```
[全部知识库] [仅当前笔记] [仅文件] [联网搜索]
```

#### 5. Chat 回答里的内容溯源

在 context 构建时给每个文档片段加 ID 标记，让 AI 在回答中引用：
```
> 📄 来源：《2025规划.md》
```

### P2 — 锦上添花

#### 6. 用户记忆系统

在 LLM settings 里加一个"个人偏好/画像"字段：
- 用户是做什么的、偏好什么风格、常用什么工具
- 每次 chat 拼到 system prompt 末尾

#### 7. 笔记的 AI 模板生成

创建页面加下拉："AI 生成模板"，选类型 → 一键生成大纲

## 九、总结

我们最大的问题不在功能数量，在 **AI 不够懂用户的数据**。

现在 AI Chat 是"有了"，但它看到的是用户所有文件的前 200 个字符，找不到真正需要的信息。

ima 最值得学习的不是那些花哨的播客/脑图/知识号，而是 **"让 AI 真正理解知识库"**。把这个做好，加上隐私牌和待办管理，产品就有了灵魂。

**ima 验证了这个市场的存在，但没有占领它。**

# Old Z vs Obsidian 竞品分析

> Obsidian 版本：1.12+（2026 年）
> 用户量：全球千万级，笔记软件赛道的"Linux"

---

## 一、Obsidian 是什么

Obsidian 是一个**本地优先的 Markdown 知识库**，核心卖点：

- **纯文本 Markdown**：每条笔记是 `.md` 文件，存本地硬盘
- **双向链接 `[[ ]]`**：笔记之间互相关联，形成知识网络
- **关系图谱**：力导向图可视化全部笔记连接
- **2000+ 社区插件**：Dataview（查询引擎）、Templater（模板）、Canvas（无限画布）等
- **完全免费**个人使用，Sync $4/月，商业 $50/年

---

## 二、Obsidian 的核心优势 — Old Z 该学的

### 1. 🔗 双向链接 `[[wiki-link]]`（知识网络的神经元）

这是 Obsidian 最核心的差异化能力。只需在笔记里写 `[[另一篇笔记]]`，自动建立双向连接。

**Old Z 现状**：Notes 没有 `[[` 链接语法。笔记之间的关联只能通过手动的 `linkedFileIds` / `linkedTodoIds` 实现。文件、笔记、待办之间的跨模块关联更是缺失。

**该学什么**：
- 笔记正文中支持 `[[笔记标题]]` 自动链接（在 MDXEditor 里扩展 link plugin）
- 每篇笔记底部自动显示"反向链接"——哪些笔记提到了我
- 同理：`[[todo:xxx]]`、`[[file:xxx]]` 实现跨模块引用
- 这不能靠 AI 代劳——AI 辅助建立关联可以，但**人工随手加链接**的体验是 AI 做不到的

### 2. 🌐 知识图谱可视化

Obsidian 的 Graph View 是"第二大脑"这个概念的视觉锚点。新用户看到图的瞬间就被说服了。

**Old Z 现状**：你的技术架构文档里设计了知识图谱节点类型，但实际代码中没有实现。

**该学什么**：
- 这是 Old Z 最大的 UI 亮点缺失。你现在有文件、笔记、待办、标签、时间线，数据关联是全的，但没有可视化。
- 用 D3.js / vis.js / cytoscape.js 做一个知识图谱页面，节点 = 文件/笔记/待办/标签，边 = 引用/标签共现
- 这不需要 AI，纯靠已有数据，但效果是"一图胜过千言万语"

### 3. 📝 本地优先 + 纯文本 = 数据主权

Obsidian 用户最大的忠诚度来源：**我的数据完全是我的**。`.md` 文件存在硬盘上，任何工具都能打开。

**Old Z 现状**：数据存在 MySQL + OSS。用户不能直接在 Finder/资源管理器里浏览。换工具 = 数据全丢。

**该学什么**：
- 导出功能：一键导出全部笔记为 Markdown 文件夹
- 或者：可选本地存储模式——数据存在 `~/Old-Z/data/`，数据库文件明文可读
- 这是 ima 做不到的，Obsidian 做得最好的，你应该在中间的甜蜜点

### 4. 🧩 插件化 = 生态护城河

Obsidian 2000+ 插件，用户自己造轮子然后分享。Dataview（类似 SQL）、Templater（模板引擎）、Excalidraw（画板）——这些都不是官方做的，但都成了核心卖点。

**Old Z 现状**：零插件系统，所有功能都是 hard-code。

**该学什么（长期）**：
- 不需要做完整的插件系统（太重了）
- 但可以**开放工具链**：提供 REST API + 本地 CLI，让用户和 AI Agent 能操作 Old Z 的数据
- 甚至更简单：把数据层做成 SQLite 可读写格式，用户可以用任何脚本操作

---

## 三、Obsidian 的致命弱点 — Old Z 的机会

### 1. 🤖 没有内置 AI（最大的软肋）

Obsidian 的 AI 完全依赖社区插件（Copilot、Smart Connections、ChatGPT MD），问题：
- **索引大库时崩溃**：10,000+ 笔记时 Copilot 抛出 `RangeError: Invalid string length`
- **插件断更风险**：作者可能随时弃坑，更新 Obsidian 版本就炸
- **嵌入质量差**：用同一模型，检索到的内容相关性远不如专业 RAG 工具
- **占用主线程**：索引时 UI 卡死
- **中文检索质量差**：Copilot 对中文的向量检索效果明显弱于英文

**→ Old Z 的机会**：你的 AI 是**内置原生**的。不需要用户装插件、配 API Key、调 embedding model、排各种 bug。这就是你和 Obsidian 最核心的差异点——**开箱即用的 AI 知识库**。

### 2. 📎 非 Markdown 文件管理一塌糊涂

存储 PDF/图片可以，但你没法：
- 拖拽 PDF 进去直接预览
- 看 Office 文档（DOCX/XLSX/PPT）
- 播放音视频
- 全文搜索 PDF 内容

用户得装一堆插件（或者干脆不存附件到 Obsidian）。

**→ Old Z 的机会**：你的 FilePreview 支持 PDF/DOCX/Excel/图片/音频/视频/CSV/HTML/文本——**共 9 类格式预览**。这是 Obsidian 完全做不到的。

### 3. 📋 没有原生任务管理

Obsidian 的任务管理全依赖插件（Tasks、Todoist Sync），体验碎片化：
- 不同插件之间的任务不能互通
- 没有截止日期视图
- 没有"今天要做什么"的 Dashboard

**→ Old Z 的机会**：Dashboard 的日程视图 + 过期待办 + 未来 7 天预览，这是 Obsidian 用户常年期待的体验，但他们得装 3-5 个插件 + 写 Dataview 查询才能勉强实现。

### 4. 📚 学习曲线极陡

新用户打开 Obsidian → 空白的库 → "我该做什么？"

你得学 Markdown、学双链、学 Dataview 语法、学 Templater、配插件、调 CSS……整个过程可能持续数月。

**→ Old Z 的机会**：你是一个**"打开就能用"**的应用。拖拽文件 → AI 自动处理 → Dashboard 展示。不要求用户是 Markdown 高手或效率控。

### 5. 🔍 搜索越来越慢

1.9 版本后大量用户反馈搜索变慢，插件越多越卡。

**→ Old Z 的机会**：一旦你做完 RAG 向量检索，搜索速度和质量会远超 Obsidian 的全文匹配。

## 五、该怎么跟 Obsidian 共存（而非竞争）

**Obsidian 用户和 Old Z 用户其实是两类人：**

| Obsidian 用户 | Old Z 用户 |
|--------------|-----------|
| 喜欢折腾配置 | 喜欢开箱即用 |
| Markdown 原教旨 | 不关心格式 |
| 用插件搭系统 | 系统已经搭好 |
| 纯文本至上 | 多媒体混杂（PDF/图片/视频） |
| 知识沉淀 > 行动 | 行动导向 |
| 享受学习曲线 | 需要零学习成本 |

**结论：不存在直接竞争。** 你能抢的用户是：
1. 试过 Obsidian 但被复杂度劝退的人（这个群体很大）
2. 需要 AI 但不想折腾插件的人
3. 需要同时管理文件和笔记和待办的人（Obsidian 管不好文件）

## 七、一句话总结

**Obsidian 是最好的笔记软件，但不是最好的 AI 知识管理工具。**

它的 AI 是"拼凑出来的"——靠第三方插件、靠用户自己配 API Key、靠忍受索引崩溃和检索漂移。而你的 Old Z 有**原生 AI + 完整文件管理 + 待办行动闭环**，这些都是 Obsidian 做不到或做不好的。

但 Obsidian 有两个东西你必须学：**双向链接**和**知识图谱**。它们是"第二大脑"这个概念的体验锚点，有了它，用户才能真正感受到"我的知识在生长"。没有这两个，你的 AI 再聪明，用户也看不到知识之间的连接。
