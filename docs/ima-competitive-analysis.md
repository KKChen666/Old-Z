# Old Z vs 腾讯 ima 竞品分析 & 改进清单

> 调研日期：2026-07-08
> ima 版本：2.5.x（截至 2026 年 5 月）

---

## 一、ima 是什么

腾讯于 2024 年 11 月发布的 AI 智能工作台，定位"会思考的知识库 / 第二大脑"。覆盖 Win/Mac/iOS/Android/小程序等 9 个端。

核心功能：搜（问答检索）+ 读（文档解读）+ 写（AI 创作）

---

## 二、ima 的 7 大硬伤 → Old Z 的机会

### 1. 容量焦虑（最致命）
- 免费版仅 2GB，重度用户几天用完
- 用户原话："2G 够谁塞啊，我微信收藏早破 10G 了"

> **我们的机会**：OSS 成本极低，轻松做到免费 50G+

### 2. 隐私焦虑（第二大痛点）
- 所有文件强制上传腾讯云，必须微信/QQ 登录
- 协议对数据是否用于训练模型、是否加密等描述模糊
- 法律/金融/医疗等行业完全不敢用

> **我们的机会**：Electron 桌面端天然支持本地优先架构

### 3. 生态围墙
- 只打通腾讯文档，WPS/飞书/Notion 全不通
- 资料需要手动搬运

> **我们的机会**：做生态中立的工具

### 4. 组织能力弱
- 知识库扁平化设计，没有文件夹分类
- "知识库"和"笔记"两个模块割裂，操作逻辑不一致

> **我们的机会**：Files + Notes + Todos 三大模块无缝关联

### 5. 搜索质量不稳定
- 会混入共享知识库内容，缺少"只搜我的库"开关
- 事实类问题偶有幻觉

> **我们的机会**：标注"仅我的库 / 仅当前文档 / 跨库"的显式检索范围

### 6. 无法离线使用
- AI 推理全依赖云端，断网就废
- 不支持本地模型接入（Ollama/llama.cpp）

> **我们的机会**：Electron 端可以集成本地小模型

### 7. 不适合做任务管理
- ima 偏"查阅型知识库"，没有真正的待办/日程管理

> **我们的机会**：知识管理 + 行动管理一体化

## 四、差异化定位

> **"本地优先的 AI 知识行动力工具 —— 不只是存知识，更帮你把事情做了。"**

### 短期（1-2 周可落地）
1. 首页加一句："你的文件存本地，不上云，不训练模型"
2. 突出 Dashboard：日程 + 待办 + 统计是 ima 没有的东西
3. 文件关联 todo/note：让知识直接变成行动项

### 中期（1-2 月）
1. 本地模型集成：离线摘要和标签生成
2. 文件夹/目录树：知识分类 vs ima 的扁平化
3. 端到端加密 + 纯离线模式

### 长期护城河
1. 开放生态：浏览器插件 + API + 第三方连接器
2. 本地大模型：等端侧推理成熟，我们是最早准备好的
3. 行动闭环：知识 → 洞察 → 待办 → 完成，完整链路

## 六、ima 比我们强的地方 → 我们该学的

### P0 — 不改就是硬伤

#### 1. 知识库 RAG 检索 vs 全量灌入 Context

**现状**（`api/services/ai.ts:265-291`）：
```typescript
// buildChatContextMessage — 把所有数据 dump 进 system prompt
ctx.todos.forEach(t => parts.push(`- [ ] ${t.title} ...`));
ctx.files.forEach(f => parts.push(`- ${f.name} ...`));
ctx.notes.forEach(n => parts.push(`- ${n.title}: ${n.content.slice(0, 200)}`));
```

问题：
- 用户有 100 个文件时，context 太长被截断或塞不进去
- 文件内容只截取前 200 字符，找不到需要的信息
- 回答没有出处标注

**改进方案**：
1. 文件/笔记上传时做 embedding → 存向量
2. 提问时向量检索 top-5 相关片段 → 精准注入 context
3. 回答后标注来源：`> 📄 来自《季度财报.pdf》`

#### 2. AI 与编辑器的融合

**现状**：编辑器没有 AI 入口

**改进方案**：
- 笔记编辑器里选中文字 → 弹出 AI 浮动菜单（"润色 / 扩写 / 摘要 / 翻译"）
- 快捷键 `Ctrl+K` 呼出 AI 内联输入框
- 不离开编辑界面就能完成 AI 操作

#### 3. 文档上传后的自动 AI 处理

**现状**（`Dashboard.tsx:111-164`）：上传 → 存文件 → 手动打标签 `['拖拽上传']` → 结束

**改进方案**：
- 上传完成后自动调用一次 AI："给这个文件起 3-5 个标签，写一句中文摘要"
- 标签自动填充、摘要存为文件属性

### P1 — 重要但可以排后

#### 4. 搜索范围显式切换

Chat 输入框上方加标签行：
```
[全部知识库] [仅当前笔记] [仅文件] [联网搜索]
```

#### 5. Chat 回答里的内容溯源

在 context 构建时给每个文档片段加 ID 标记，让 AI 在回答中引用：
```
> 📄 来源：《2025规划.md》
```

### P2 — 锦上添花

#### 6. 用户记忆系统

在 LLM settings 里加一个"个人偏好/画像"字段：
- 用户是做什么的、偏好什么风格、常用什么工具
- 每次 chat 拼到 system prompt 末尾

#### 7. 笔记的 AI 模板生成

创建页面加下拉："AI 生成模板"，选类型 → 一键生成大纲

## 七、不该学 ima 的地方

| ima 的做法 | 为什么不该学 |
|-----------|-------------|
| 微信/QQ 登录 | 隐私牌是最大差异点，做邮箱/本地账号 |
| 数据强制上云 | 做**本地优先 + 可选云同步**，这是 ima 的软肋 |
| 知识库广场（公开共享） | 个人工具不需要社交 |
| 知识号/付费知识库 | 太重了，不是做平台的 |
| 播客/AI 视频生成 | 功能蔓延，ROI 极低 |
| 100 万成员共享知识库 | 企业协作不是我们的赛道 |

## 九、总结

我们最大的问题不在功能数量，在 **AI 不够懂用户的数据**。

现在 AI Chat 是"有了"，但它看到的是用户所有文件的前 200 个字符，找不到真正需要的信息。

ima 最值得学习的不是那些花哨的播客/脑图/知识号，而是 **"让 AI 真正理解知识库"**。把这个做好，加上隐私牌和待办管理，产品就有了灵魂。

**ima 验证了这个市场的存在，但没有占领它。**
